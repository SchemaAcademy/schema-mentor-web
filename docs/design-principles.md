# SchemaMentor：存储引擎交互教学设计原则

这份文档是本项目后续 AI 设计与开发的默认约定。目标不是制作一个漂亮的数据库控制台，而是让学习者能回答：**我做了什么、内部发生了什么、为什么会发生、换一个条件会怎样。**

## 1. 先定义学习问题，再设计页面

每个实验只承诺一个可验证的学习目标。先写一句问题，再选择操作和图形。

- B+ Tree：节点满了以后，再插入一个键会怎样？
- LSM Tree：数据先进入内存，什么时候成为有序的磁盘文件？
- WAL：日志已经写入、数据页还没落盘时，崩溃后如何恢复？
- Bitcask：同一个键写两次，为什么读取会得到最新值？

页面按照「预测 → 操作 → 观察 → 解释 → 改变条件再验证」组织。每个实验提供一个最小、可复现、能触发关键现象的预设，不要求用户先造数据。一次只突出一个因果关系；深层细节按需展开。

## 2. 信息架构：发现、实验、理解

| 页面       | 用户要解决的问题             | 核心内容                                       |
| ---------- | ---------------------------- | ---------------------------------------------- |
| 探索空间   | 我能在这里学到什么？         | 一句话价值、可操作的小示例、真实可用的实验入口 |
| 交互实验室 | 哪个实验适合我？             | 主题、问题、难度、预估时间、可用状态           |
| 实验详情   | 这次操作为什么产生这种结果？ | 操作栏、结构画布、时间轴、同步解释             |
| 学习指南   | 我应该怎样观察？             | 前置概念、观察任务、反思问题、模型边界         |

首页只有一个主行动「开始第一个实验」。不堆砌虚假的学员人数、课程数量、进度、评分或用户头像。未实现的主题显示“筹备中”，不制作会跳到 404 的入口。只有真实完成并可访问的内容，才允许成为主按钮。

## 3. 实验页的空间约定

桌面布局从上到下是：主题与学习目标、模式和预设、实验主体、模型边界。实验主体左侧放结构与操作，右侧放当前步骤解释。

- 结构画布占主要面积；不要让表单占据视觉中心。
- 参数靠近其影响的结构；输入后立即显示反馈，不让用户猜测是否执行。
- 时间轴紧邻画布，提供上一步、下一步、播放/暂停、重播、速度、拖动进度。
- 解释与当前帧来自同一份状态，不能出现图已经变了、文字还在解释上一帧的情况。
- 移动端顺序：操作模式 → 画布 → 播放器 → 输入 → 当前解释。复杂图允许局部横向滚动，整页不得横向溢出；不要把节点缩成无法阅读的小字。
- 可变宽度内容使用 `minmax(0, 1fr)` / `min-width: 0`。横向图容器应左侧可达，不能因为强行居中而裁掉左半部分。

## 4. 视觉语言：安静的工具，明确的变化

采用浅色、轻边框、低饱和背景。结构关系比装饰更重要。首页可以更有编辑感，实验页必须让人长时间看得清楚。

| Token / 角色   | 当前值或范围                   | 用法                           |
| -------------- | ------------------------------ | ------------------------------ |
| 页面背景       | `--background: #f8f9fb`        | 给白色实验面板留出层次         |
| 内容表面       | `--surface: #ffffff`           | 表单、卡片、主要可读区域       |
| 主要文字       | `--foreground: #202c3d`        | 标题、关键结论                 |
| 正文辅助色     | `--muted: #647082`             | 解释与描述                     |
| 主强调         | `--accent: #315ed5`            | 主操作、当前键、当前路径       |
| 浅强调背景     | `--accent-soft: #edf2ff`       | 当前选项与轻提示               |
| 边框           | `--border: #e4e8ef`            | 区分区域，不作为唯一状态信号   |
| 间距           | 4 / 8 / 12 / 16 / 24 / 32 / 48 | 同层元素统一间距               |
| 圆角           | 6–10 px                        | 表单和面板保持同族，不全做胶囊 |
| 正文           | 中文系统字体                   | 不依赖运行时下载远程字体       |
| 键、代码、指标 | 系统等宽字体                   | 数字对齐，便于比较             |

蓝色代表当前关注点；其他颜色只用于语义区分。节点类型还必须有文字标记（INDEX / LEAF）；溢出、失败、成功还必须有明确文字。不要仅靠红绿或闪烁表达含义。

中文是主要教学语言，标准英文术语保留便于读源码。装饰性英文小标题可以小一些；解释正文、关键状态和操作文字保持可读。不要为了“高级感”不断降低文字对比度。

## 5. 动画必须解释变化

动画的单位是语义事件，不是随意的延时。当前 B+ Tree 采用：

1. 定位：逐层比较分隔键，高亮走过的节点与指针。
2. 写入：在目标叶节点显示新键，保留排序；必要时展示明确标记的临时溢出状态。
3. 分裂：展示分裂后的节点与索引更新，说明分隔键为什么出现。
4. 完成：展示稳定结构及结论，让学习者有时间观察。

当前实现把所有级联分裂合并为一帧，并明确说明；以后可以细化为叶分裂、父节点接收分隔键、内部节点分裂、新根创建。不要把一次最终结构切换宣称成完整的每层级联演示。

动画约定：

- 已存在节点保持稳定 ID。位置变化使用同一元素的位移过渡，而不是整图销毁重建。
- 键插入、路径访问、节点分裂分阶段出现；避免多个无关焦点同时运动。
- 控件反馈约 120–180 ms，结构过渡约 450–650 ms，每个教学步骤默认停留约 1400 ms。这些是项目起点，不是真实存储延迟。
- 不自动开始长动画。用户触发后才播放；暂停和单步操作始终可用。
- 暂停也应停止装饰性的路径流动，静态高亮仍须保留。
- 支持 `prefers-reduced-motion`：去掉位移与流动动画，保留瞬时状态变化、时间轴和完整解释。
- 当帧过多或图过大时，限制演示规模并解释上限；不要悄悄丢掉节点。

## 6. 模型正确性优先于视觉叙事

领域模型、教学事件、图形布局、播放器分别负责不同的事：

```text
操作 + 参数
    ↓
确定性的领域模型（lib/bPlusTreeSimulator.ts）
    ↓
不可变教学帧（lib/bPlusTreeLesson.ts）
    ↓
帧索引 ──→ 树图 / 解释 / 指标 / 当前操作
```

图形组件不能靠动画时间推算真实状态。上一帧和下一帧应能直接恢复，不需要倒放副作用。不把动画延时写进领域算法。

每个教学帧包含：结构快照、阶段、焦点实体 ID、操作值、标题、解释、所属操作编号。未来多个模拟器共用播放器前，应先验证它们确实有相同需求，避免过早创造复杂框架。

区分真实系统与教学模型：

- 节点访问次数不直接等同于磁盘 I/O；缓冲池和页缓存会改变实际成本。
- 容量为“最多几个键”，不能冒充真实的页面字节数或含糊使用“阶数”。
- 当前只模拟唯一整数键，不模拟记录 payload、删除、事务、并发、日志或持久化。
- 叶节点虚线表示有序关系；当前模型没有真实存储 next 指针。
- 模型中的临时溢出不是稳定的 B+ Tree 状态，必须明确标记。
- 叶节点分裂时分隔键被复制；内部节点分裂时中间键被提升。讲解时不能混用。

## 7. 所有操作都要有清晰契约

| 情况                   | 预期行为                                     |
| ---------------------- | -------------------------------------------- |
| 空值、小数、超范围数字 | 原位显示错误及允许范围；保留输入供修正       |
| 重复键                 | 明确说明跳过；树保持不变                     |
| 查找不存在的键         | 显示走过的路径并明确“未找到”                 |
| 播放到末尾             | 停止播放，按钮变为重播                       |
| 拖动、前后单步         | 暂停自动播放，定位到对应快照                 |
| 更换参数/预设          | 清理播放定时器，重建序列，回到起点           |
| 自定义插入             | 明确追加到完整序列末尾，而非悄悄分叉历史     |
| 切换到查找             | 明确基于完整序列最终树查找                   |
| 重置                   | 恢复当前预设，回到初始帧，保留容量与速度偏好 |
| 规模上限               | 显示上限与重置路径，拒绝继续添加             |

使用原生 button、label、input、select。图标按钮必须有可读名称；当前模式使用 `aria-pressed`，页面导航使用 `aria-current`；错误用 `role="alert"`，教学解释用 `aria-live="polite"`。给树图文字替代描述。键盘能走完核心学习流程，焦点始终可见。

无障碍参考：不用颜色作为唯一信息载体（[WCAG 1.4.1](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)）；非必要交互动画可关闭（[WCAG 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)，此条为 AAA）；点击目标满足尺寸/间距条件（[WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)）。本项目以这些原则指导实现，不宣称已完成 WCAG 合规审计。

## 8. 给 AI 的开发流程

1. **读项目**：阅读本文件、根目录 AGENTS.md、相关领域模型及已有组件。先验证现有能力，避免把 README 的规划当成已实现功能。
2. **写学习契约**：说明目标问题、先验知识、默认数据、核心操作、关键帧、用户应该观察到的结论。
3. **先做正确的状态**：实现确定性操作、不可变快照和必要的领域测试。包括不存在、重复、容量边界、级联变化等。
4. **再建立布局**：沿用导航、页面留白、颜色、卡片、TreeDiagram 等现有组件。一个页面一个主操作，不重新创造另一套视觉风格。
5. **加入解释与动画**：从同一帧驱动画布和说明；让用户能暂停、单步和回放。不要用一段预录动画代替可执行模型。
6. **验证完整路径**：从首页进入实验，执行操作，修改参数，回放，重置，再用手机宽度和键盘走一遍。
7. **交付可检查结果**：运行 lint、领域测试、构建，打开本地页面；说明本次完成与模型的实际边界。

## 9. 可直接复用的 AI 任务模板

```text
请在 SchemaMentor 中实现 [主题] 交互实验。
先阅读 AGENTS.md 和 docs/design-principles.md，沿用现有导航、布局与设计 token。

学习问题：[用户应该能解释的一个因果问题]
目标读者/前置知识：[例如了解 key-value，但不了解页和索引]
默认场景：[少量数据、具体操作、可复现的触发条件]
允许操作：[插入/读取/flush/...，只承诺本次会实现的]
关键观察：[发生变化的对象、触发原因、结果、保持不变的约束]
简化边界：[省略哪些真实系统细节，哪些只是概念映射]
完成标准：[用户做什么，可以观察到什么，怎样验证理解]

先建立领域状态和语义事件，再做结构画布、同步解释与播放器。
提供默认场景、自定义输入、错误反馈、暂停、单步、重播和重置。
未完成的功能明确标记，不添加无行为按钮或虚构指标。
检查桌面/移动端、键盘、减少动画、边界输入及状态一致性。
通过 lint、相关测试、静态构建后，在本地打开最终页面。
```

## 10. 页面验收清单

- [ ] 首屏能回答“学什么、怎么开始、为什么值得操作”。
- [ ] 默认场景可以稳定触发要讲解的机制。
- [ ] 操作、结构、解释、指标来自一致的状态。
- [ ] 动画有因果含义；暂停后仍能读懂，不依赖动画才能理解。
- [ ] 重放完全确定，上一帧不被之后的操作修改。
- [ ] 重复/不存在/无效输入/规模上限都能正确反馈。
- [ ] 所有导航真实可访问；筹备中的功能不伪装成已上线。
- [ ] 小屏幕没有整页水平溢出，复杂图可以从最左端滚动查看。
- [ ] 字体、对比度、焦点、标签、点击目标、减少动画经过检查。
- [ ] 使用教学模型的准确措辞，没有把可视化指标冒充真实性能数据。
- [ ] 测试覆盖关键领域约束，lint 和构建通过，本地交互已实际操作。
